# 开发过程

此文整理可公开的讨论、决策与结果。原始聊天、账号资料、私人日志及系统镜像不原样上传。

## 设备准备与首次实验

Windows 11 最初没有可用 ADB 命令；补充工具和授权后核对 `dipper`、MIUI 与解锁状态。早期 FASTBOOT 出现传输超时、USB 枚举失败，经历线材/接口/驱动排查；最终取得可用恢复入口。重要数据和原引导先备份，主机空间较大的输入与备份放到其他磁盘。

## iOS 进入与外设边界

初始 UEFI 存在 ArmCpuDxe 异常，使用已验证构建参数后进入 iOS。后续明确区分能进入桌面、可关联 Wi-Fi、真正外网访问，以及相机/音频等上游未支持的功能。不同轮次之间完整重启，不沿用已经返回的内核直接重复运行。

## 双系统与持久保存

持有人明确需要本机菜单选择 Android/iOS，并保留用户设置。组合引导保留原 Android 内核/DTB/ramdisk，UEFI 提供 iOS 入口。早期恢复旧存档会导致桌面异常，之后用新存档验证中文、外观、Wi-Fi 和应用保留。周期与退出保存需要足够时间；大存档曾超出较短结束等待预算。

## 更新、应用与容量

同步近期显示优化和蓝牙工作；默认仍保留原分辨率。用户确认 Safari 外网、蓝牙连接但无声音。两个本机应用经执行权限修正后可基本启动并重启保留。截图失败最终定位到真实可写数据卷余量不足，增加有界 RAMFS 上限后局部验证恢复；没有完成数十 GB 闪存写入或半盘迁移。

## 引导界面

界面从深色列表发展为浅色玻璃卡片，保留用户给定的三个 SVG。署名移到底部一行，加入英文副标题，之后将全部界面文字改为真实控件，标题略微缩小。高级选项与子菜单统一布局。

两次设备反馈补齐了主机模型：返回按钮的布尔参数实际为 enabled；SVG 解码固定按 2 倍采样。后者使标志被放大裁切，已用固定布局盒和包含式缩放修正。高级选中也改为单独活动项，清除系统勾选并正确更新底部动作。ASAN 发现并修复页面释放后的焦点访问。

加入 10 秒默认 Android，首次输入取消本次开机计时，返回不恢复。经主机和持有人设备验证后，仅更新 boot，完整回读一致，原恢复和分区表保持。

## 公开整理

维护者要求公开仓库与新版 UI 固件，但排除 Apple 系统文件。公开物因此采用纯 UI EFI/FFS 组件与完整对应 UI 源码。为保留原界面，不把替换字体版作为同款发布；字库改为本机提供的资源，三个 SVG 原件原样入库。发布范围、附件取舍和验证差异分别记录，未完成的存储、关机等问题不标记为修复。
